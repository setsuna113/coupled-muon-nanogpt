\paragraph{To rebuild this report end-to-end:}

\begin{verbatim}
git clone <repo>
cd coupled-muon-nanogpt
uv sync --extra docs
python docs/figures/fetch_all.py --refresh   # only when wandb sync changed
python docs/figures/make_all.py              # regenerates every fig+tab
latexmk -pdf -outdir=docs/build docs/report.tex
\end{verbatim}

\paragraph{Sync state at the time of this snapshot.}
The data described above is the report-time snapshot. Stage~1 is fully synced at 75/75 expected cells. Stage~2 is fully synced at 270/270 cells (88 diverged, 182 converged). The \S d.4 ablation project has 106 synced cells (one cell past the originally planned 105 — the extra cell is a re-run of a transiently-failed slot, identical configuration). When additional cells arrive, refresh the parquet via \code{fetch\_all.py --refresh} and re-run \code{make\_all.py}; the entire report is driven from these snapshots.

\paragraph{Data lineage in the codebase.}
The per-cell numeric source of truth is \code{<results-dir>/<run\_id>/metrics.jsonl}; the wandb cloud copy is a synced mirror. Provenance for which sweep produced which cell:
\begin{itemize}
\item Stage 1: \code{configs/sweeps/A0\_stage1\_muon.yaml} (50 cells) + \code{configs/sweeps/A0\_stage1\_adamw.yaml} (25 cells).
\item Stage 2: \code{configs/sweeps/lr\_grid\_dense\_muon.yaml} (180 cells) + \code{configs/sweeps/lr\_grid\_dense\_adamw.yaml} (90 cells).
\item \S d.4 ablations: \code{configs/sweeps/\{coupled\_steps\_ablation, final\_polish\_ablation, pair\_ablation, coupled\_x\_polish, muon\_ns\_budget\}.yaml}.
\end{itemize}
